# 第三轮：不对称打包与只恢复中间系数

## 结论与证据层级

本轮找到两个实质改进：**让一侧保留完整 E2M1 数值域的不对称打包**，以及**允许垃圾位损失、仍精确恢复目标点积的 middle-only 方案**。后者可以沿同一 GEMM 的 K 维压缩，不要求业务上恰好有两个独立 GEMM。

所有结果实际运行于此前已通过 5,000 个公开 V100 硬件回执逐位验证的 V100 数值模型。没有新增 GPU 实测，也没有吞吐或训练收敛结果。模型代码和固定上游快照在 `../../numerics/`；运行前仍验证冻结的来源清单。前两轮文件没有改动。

最短复跑命令，从仓库根目录执行：

```bash
python3 simulation/round3/math/round3_math.py
```

默认每个候选 2,048 个随机样例，每个合成分布 2,048 个长度32的块，固定种子 `20261123`。仅需要 NumPy 和同仓库的 `simulation/numerics`。输出 `round3_math_results.json`。`PROOF.md` 给出完整界限、signed decoder 推导及反例。

## 1. Middle-only 是主要改进

仍令 `q=2*x`，使用 E2M1 的七值子集 `q∈{-3,-2,-1,0,1,2,3}`。把同一点积的两条子序列打包为：

\[
P=a_0+512a_1,\qquad Q=b_1+512b_0.
\]

乘积中间系数是所需结果 `T=sum(a0*b0+a1*b1)`。两端的交叉项是垃圾，允许其中的低位丢失。我们不再要求恢复前一轮的两个独立输出。

| 压缩后的 K | 原点积项数 | 实跑样例 | 目标错误 | packed 和不再精确的样例 | packed 和最大误差 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 8 | 16 | 4,531 | **0** | 1 | 1 |
| 12 | 24 | 4,531 | **0** | 81 | 4 |

这是“packed 运算不完全精确，但有用输出仍精确”的实际数值证据。不是用容差掩盖最终点积错误。

### 一条可以直接检查的阳性样例

compressed K=8：

```text
a0 = [1,0,0,0,0,0,0,0]
a1 = [3,3,3,3,3,3,3,3]
b0 = [3,3,3,3,3,3,3,3]
b1 = [1,0,0,0,0,0,0,0]
```

两边的 packed 输入都是 `[1537,1536,1536,1536,1536,1536,1536,1536]`。

- 精确 packed 和：**18,877,441**。
- V100 模型结果：**18,877,440**，确实丢了 1。
- 目标中间系数：**6**。
- 浮点分层解码与 signed bitfield 解码：都得到 **6**。

详细输入、每个 BFMA4 的对齐 trace 及结果保存在 JSON 的 `candidates[label=middle_q3_compressed_k8].first_loss_with_correct_output`。

K=12 的充分误差界为 18。垃圾低系数至多108，因此垃圾加误差至多126，小于半 radix 256；目标中间系数至多216，也落在 signed 9-bit 范围内。这个余量保证目标精确，而非仅凭随机测试作判断。

### 最短数学解码式

无需先求出高位垃圾：

```text
u = int32(z) + 256
T = signed_bitfield_extract(u, 9, 9)
```

z 是整数且绝对值小于 `2^25`，所以转 int32 无损；严格 guard 排除了正负数的舍入中点。所有 middle 样例同时验证这个解码式，错误为 0。返回 FP32 输出还需转换和缩放，实际指令数及性能应由相应的编译和硬件实验报告。

### 一个 MX32 块准确需要几次解码？

原 K32 配对后是 compressed K16，不能一次累加完再解码。当前正确流水线是 **8+8 两段**：每段两次 BFMA4，再进行一次 middle decode。因此每个原始 K32 块需要 **4 次 BFMA4、2 次解码**；普通路径是8次 BFMA4。2,049 个完整块的数值测试全部正确。

配对必须位于同一 scale product 范围内。若跨越不同 MX32 缩放块，不能直接把加权不同的两条子序列混成一个中间系数；JSON 中保留了相同 packed 输出对应不同物理答案的反例。

## 2. 不对称编码让一侧保留完整 E2M1

两路 A 使用 ternary q，B 使用完整15值 E2M1 q：

```text
Apack = a0 + 512*a1
Bpack = b0 + 128*b1
K = 4
```

这种编码恢复两个独立点积。低路最大48，小于64；高路周围所有干扰至多30,768，小于32,768；packed 和绝对值至多3,176,496。FP16 输入和 V100 累加均精确。

**4,154 个样例全部正确**，包含完整 B 数值域的极值与混合符号，并验证四条 lane 使用独立二次幂缩放后的结果。其用途是 ternary activations × full-E2M1 weights 等不对称场景，不能称为双侧完整 MXFP4。

共享 RHS 的两条变体也通过模型验证：

| A 的 q 域 | B 的 q 域 | A 打包 radix | K | 样例 | 错误 |
| --- | --- | ---: | ---: | ---: | ---: |
| -3…3 | 完整 E2M1 | 512 | 4 | 2,810 | 0 |
| -1,0,1 | 完整 E2M1 | 1024 | 32 | 2,210 | 0 |

全轮共筛选47,040个参数组合的充分条件，并运行18,236个候选样例。未通过充分条件不等于该方案已被证明不可能。

## 3. 完整 MXFP4 数据是否容易准入？实际不一定

为避免把“有效子域”误当成普通训练数据，我们生成了五种分布，每种2,048个长度32块，按 OCP 风格的 max scaling 和 E2M1 最近偶数舍入量化。三个稠密分布的每个块都出现了 q=8 或12的最大幅度码，**没有自动落入七值或三值子域**。

下面的“pair准入率”要求共享 RHS 的两条 A 行各自满足 q3 条件，使用相同配对跨方法对比。公共2幂或最大公约数被约去后，必须在输出端准确乘回。

| 合成分布 | 原始 q3 pair 准入 | 约公共2幂后 | 约 gcd 后 | middle 原K16的 A/B 均准入，约2幂后 |
| --- | ---: | ---: | ---: | ---: |
| Gaussian | 1.453% | 5.432% | 6.213% | 0% |
| Laplace | 6.714% | 11.450% | 12.231% | 0.049% |
| Student-t(3) | 11.365% | 16.895% | 17.578% | 0.195% |
| 90%零的 Gaussian | 55.322% | 95.044% | 95.898% | 49.512% |
| Ternary 正对照 | 0% | 100% | 100% | 100% |

这只是合成数据，在准入比较中 A/B 从同一分布配对；不是实际模型权重、激活或梯度统计。稀疏场景还应与直接利用稀疏性的基线比较。gcd 包含3等因子时，新的内部因子不再是一个 E8M0 二次幂 scale；它是精确算术重分解，需要另行后乘，不能称为免费的标准 MX 格式转换。

## 4. core+residual 修复可以正确，但密集修复会增加工作

我们也实际运行了 `A=clip(A,-3,3)+residual`：core 用 V100 packed 共享B路径，非零 residual 精确补回。每种分布512个两输出样例，均恢复完整 E2M1 点积。补丁的整数幅度足够小，可以精确表示为 FP32；这部分是算术正确性及操作计数，不是稀疏 CUDA 性能测试。

| 分布 | 每两个输出平均额外 residual 标量乘积 | 至多1个补丁的 pair 比例 | 平均非空指数桶数 |
| --- | ---: | ---: | ---: |
| Gaussian | 3.556 | 8.252% | 2.601 |
| Laplace | 2.536 | 25.342% | 2.424 |
| Student-t(3) | 2.181 | 34.814% | 2.296 |
| 90%零 Gaussian | 0.566 | 89.722% | 0.679 |

这些数不能直接折算成 Tensor Core 周期：索引、gather、分支、寄存器和重新打包都有成本。

如果 residual 仍用密集 GEMM，两个共享B输出的成本从原来2份乘积变成1份 packed core加2份 residual，即 **3对2，算术工作为1.5倍**。两侧都拆 core/residual 时，用 `AB=AcBc+ArB+AcBr`，若修复全走密集 GEMM，朴素打包版是5份对原来的2份。指数分桶每个 q 写成 `2^e*m`、`|m|≤3`，最多需要三个 packed 桶；Gaussian 平均2.601个非空桶，也超过两个普通乘积的基线。

因此，本轮支持继续实现 middle-only 和不对称内核，也给出了明确的适用分布限制。它没有证明普通稠密 full-MXFP4 训练会因此更快。
